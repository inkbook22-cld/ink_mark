# 네이버 블로그 임시저장

기존 업로더 코드가 없어 새로 만들었다. **본문을 붙여넣지 않고 타이핑한다.**

```
profile.json   셀렉터·타이밍. 네이버가 화면을 바꾸면 여기만 고친다 (D1)
session.mjs    계정별 영속 프로필, 로그인 확인
blocks.mjs     원고(Markdown) → 입력 블록
typing.mjs     타이핑 엔진 (key / ime 두 모드)
uploader.mjs   중복 확인 → 제목 → 본문 → 임시저장 → 검증
```

## 왜 붙여넣기가 아니라 타이핑인가

| | 붙여넣기 | 타이핑 |
|---|---|---|
| 서식 | 원본 HTML을 끌고 들어와 에디터가 재해석 — 글꼴·크기·색이 섞인다 | 에디터 기본 서식 그대로 |
| 클립보드 | 전역 자원. 업로드 중 사용자가 뭔가 복사하면 내용이 바뀐다 | 영향 없음 |
| 삽입 위치 | 에디터가 paste 를 자체 처리하면 제어 불가 | 커서 위치대로 |
| 속도 | 즉시 | 원고 한 편에 20~60초 |

느린 대신 결과가 예측 가능하다. 이 앱에서는 예측 가능성이 속도보다 중요하다.

## 두 가지 타이핑 모드

**`key` (기본)** — 한 글자씩 delay 를 두고 입력한다. Playwright 는 자판에 없는
문자(한글)를 `insertText` 로 넣으므로 `beforeinput`/`input` 이벤트가 정상 발생한다.
대부분의 에디터가 이걸로 충분하다.

**`ime`** — CDP `Input.imeSetComposition` 으로 한글 IME 조합 과정까지 흉내 낸다.
`한` 을 넣을 때 `ㅎ → 하 → 한` 순서로 조합 이벤트가 발생한다. 에디터가 `composition*`
이벤트에 의존해 입력을 처리하는 경우에만 필요하다. 3배쯤 느리므로 `key` 가 실패할 때만 쓴다.

```bash
node scripts/naver-draft.mjs --blog-id myblog --file 원고.md --title "제목"
node scripts/naver-draft.mjs ... --ime     # key 모드가 안 먹을 때
```

## 이미지

이미지는 타이핑할 수 없다. 사진 버튼 → 파일 선택 대화상자로 올린다.
블록 변환 단계에서 `![alt](path)` 를 별도 블록으로 분리해 두는 이유다.

## 중복 방지와 검증

계획의 두 요구사항을 이렇게 처리한다.

- **쓰기 전** 임시글 목록에서 같은 제목을 찾는다. 있으면 진행하지 않고
  `사용자 확인 대기` 로 돌려준다 — 덮어쓸지 새로 쓸지는 사람이 정한다.
- **저장 후** 글을 다시 열어 제목·본문 길이·이미지 수를 확인한다.
  확인에 실패하면 `저장 여부 미확인` 으로 남기고 **자동 재시도하지 않는다.**
  중복 글이 생기는 쪽이 저장 실패보다 나쁘기 때문이다.

상태값: `입력 중` → `사용자 확인 대기` → `저장 확인됨` / `저장 여부 미확인` / `실패`

## 검증 상태

`npm run test:typing` 은 로컬 목업(`scripts/mock/`)을 상대로 돈다.
검증되는 것은 네 가지다 — 한글이 타이핑으로 들어가는지, 문단이 Enter 로 나뉘는지,
이미지가 파일 대화상자로 들어가는지, 저장 후 재확인 흐름이 도는지.

**목업은 진짜 스마트에디터가 아니다.** 셀렉터가 실제와 맞는지는 사람이 한 번
확인해야 한다. 통과하면 `profile.json` 의 `verifiedAt` 에 날짜를 적는다.
현재 `null` = 미검증.

## 한계

- 굵게·크기 등 본문 서식은 아직 적용하지 않는다. 마크다운 기호는 제거되고
  평문으로 들어간다(`##` 제목도 일반 문단이 된다).
- 로그인은 자동화하지 않는다. 아이디·비밀번호를 앱이 보관하지 않는다는 뜻이다.
- 자동화가 막히거나 실패하면 내보내기 경로로 떨어져야 한다(D1). 이 모듈은
  실패를 던지지 않고 결과 객체로 돌려주므로, 호출자가 그 전환을 처리한다.
